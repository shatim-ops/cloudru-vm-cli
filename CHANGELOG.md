# Журнал изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии —
[Semantic Versioning](https://semver.org/lang/ru/). Здесь — изменения, которые
видит пользователь CLI и MCP; внутренние (тесты, cloud-e2e, api-probe,
документы для разработки) не перечислены.

## [Не выпущено] (после v1.0.0-rc.4)

### Изменено поведение

- Зона, которую API отдаёт с `enabled: false`: `deploy`, `deploy --dry-run`, `vm create`, MCP `provision` и `deploy_plan` отказывают `CONFIG_INVALID` до резервирования floating IP и создания ВМ, с открытыми зонами в подсказке. `evo init` такую зону не предлагает и предупреждает, а в `evo list-zones` есть колонка «Новые ресурсы» (открыта или закрыта). Раньше ВМ получала 422 `wrong_az`, а созданный floating IP оставался в проекте.
- `list_floating_ips`: адрес в переходном состоянии или в ошибке (`creating`, `deleting`, `error_deleting` и другие `error*`) — `available: false`, даже без привязки (раньше адрес в `error_deleting` показывался свободным).
- Kafka и Redis (`kafka_create`, `redis_create`): сначала выбирается подсеть, зона кластера и спецификации — её; регион профиля без подсети проекта в этой зоне — `USAGE` до создания (раньше брались спецификации одной зоны и подсеть другой).
- `kafka_specs`, `redis_specs`: без аргумента `zone` и региона профиля — зона ru.AZ-2, а не запрос без зоны (API отвечал ошибкой); неизвестная зона — `USAGE`; в ответе — `availability_zone` (именем, даже если зона задана UUID).
- `evo init`: зона по умолчанию — та, где у проекта есть подсеть (ru.AZ-2, если подсеть есть в ней, затем зона основной подсети); без подсетей — ru.AZ-2 первой и предупреждение.
- Группа безопасности по умолчанию — по признаку `default` из API, затем `SSH-access_<зона>`, `Default_<зона>`, `default`, затем первая по имени (раньше — первая по порядку API или по имени `Default*`); одна логика у `deploy`, `deploy_plan` и MCP `provision`.
- `security_group` из `.evo.yaml` из другой зоны — `CONFIG_INVALID` до создания ВМ; группой `Default` считаются только `Default_<зона>` и `default`, а не любое имя с префиксом.
- Подсеть ВМ — основная подсеть зоны, затем маршрутизируемая, затем порядок API; технические и неисправные — в последнюю очередь, подсеть другой зоны — никогда.
- MCP `provision`: нет подсети или группы безопасности в зоне — `CONFIG_INVALID` до резервирования floating IP и создания ВМ, как у `deploy` (раньше бралась подсеть или группа другой зоны, ВМ уходила в `error_creating`).
- `evo configure` без терминала и без единого флага — `CONFIG_INVALID` «нужны Key ID и секрет» (код 2), а не «Профиль сохранён» с кодом 0.
- `k8s_nodepools`: `cluster_id` обязателен (без него — `USAGE` с подсказкой `k8s_list`), как в API.
- `org_projects`: для ключа уровня проекта (ответ Organization API 400/403/404) — `projects: null`, активный проект и пояснение без ошибки (раньше `NOT_FOUND`, код 4); 401 — `AUTH_FAILED`, 5xx и прочие — `API_ERROR`.
- `audit_events`: размер страницы — `limit`, не больше 500; ответ 401 — «аудит не включён для проекта, обратитесь в поддержку Cloud.ru» (`API_ERROR`), 403 — «у роли ключа нет прав или аудит не включён».
- `s3_get` / `evo s3 get`: объект больше 10 МиБ — `USAGE` с подсказкой скачать S3-клиентом, без чтения целиком.
- Размер диска (`disk_create`, `disk_resize`) — не больше 16384 ГБ, проверка до обращения к облаку (раньше справка говорила «до 65536»).
- Имена загрузочного диска и floating IP — не длиннее 64 символов: длинная основа обрезается и получает короткий хеш.
- Булевы флаги деревьев, которые инструмент по умолчанию считает `true` (`--release-ip`, `--kube-api-internet`, `--embed-token`, `--force` у `secret delete`, `--public`, `--external`), объявлены со значением `true`; выключить — `--x=false`.
- Контракт ошибок MCP: у каждой ошибки инструмента есть `reason` (код из `docs/exit-codes.md`), `error` — фраза без префикса кода, `hint` — когда известен; коды выхода CLI не изменились.
- `evo status` сверяет запись с облаком (один `GET` ВМ, до 8 с): живое состояние, «не найдена (удалена вне evo)» или «не проверено: …»; `--no-refresh` — только state; запись другого проекта не проверяется (`CONFIG_INVALID`).
- `evo destroy` и MCP `destroy`: 404 по записи другого проекта не считается «ВМ уже удалена» — ничего не удаляется, запись сохраняется, подсказка — переключиться на проект записи.
- `destroy` с `vm_id`: ВМ, удалённая вне evo, — запись чистится (FIP освобождается, правила портов закрываются), ответ `already_deleted`; если `GET` не ответил 404 — ошибка, запись сохраняется.
- `evo destroy --force` — скрытый устаревший синоним `--yes` с предупреждением.
- Floating IP SNAT-шлюза не считается свободным: `release_floating_ip` его не освобождает, `fip_attach` не привязывает.
- MCP `list_images` — прежний ответ; компактный каталог с поиском — новый `image_list`.
- `deploy` отказывает до создания ВМ на образах Astra Linux, Альт и РЕД ОС (Docker из get.docker.com на них не ставится); `deploy_plan` с `compose_file` на таких образах — `USAGE`.
- Образ общего каталога, недоступный проекту, — `NOT_FOUND` (код 4) до создания ВМ (раньше 422 после подтверждения).
- Незаполненное обязательное поле образа — отказ до создания чего-либо (`USAGE` у `vm create`/`provision`, `CONFIG_INVALID` у `deploy`).
- `evo verify --json`: ключи `port`, `status_code`, `healthy`, `latency_ms`, `error`, `protocol` (раньше — имена полей Go и наносекунды).
- JSON-ошибка без подсказки — без ключа `hint` (раньше `"hint": ""`).
- `evo list-images` скрыта из справки (работает, с подсказкой про `evo image list`).
- Цена в превью ВМ (`vm create`, `deploy`, `deploy_plan`) — из API расчёта цены Cloud.ru, при отказе или тайм-ауте 5 с — оценка по тарифной карте с причиной; нулевой ответ API — не цена, кроме flavor бесплатного уровня без нового floating IP.
- `evo k8s add-addon` и `k8s_add_addon` — в v1.0 (установка плагина проверена вживую); `resolve_mode` по умолчанию `NONE`; удаление плагина — в консоли Cloud.ru.

### Добавлено

- Каталог образов: `evo image list [запрос]`, `evo image get <имя|UUID>`; MCP `image_list`, `image_get` по имени.
- `evo vm create --image <имя|UUID>`, `--meta поле=значение` (`поле=-` — из stdin без эха, `поле=@файл`), `--port`; MCP `provision`: `image`, `image_metadata`, `ports`.
- `image:` и `image_metadata:` в `.evo.yaml`, `evo deploy --image`, `evo init --image`.
- Плагины Managed Kubernetes: `evo k8s addons`, `evo k8s addon-versions`, `evo k8s add-addon`; MCP `k8s_addons`, `k8s_addon_versions`, `k8s_add_addon`.
- Витрина: `evo marketplace list` и MCP `marketplace_list` — образы и плагины одним списком.
- `evo mcp --toolsets` — агенту только нужные группы инструментов.
- MCP-аннотации инструментов (`readOnlyHint`, `idempotentHint`, `destructiveHint`).
- Человеческое превью платных команд деревьев (`vm create`, `disk create`, `pg create`, `k8s create`, `k8s add-nodepool`, `disk resize`, `s3 bucket-create`): проект, зона, flavor, цена.
- Предупреждения до создания ВМ: подсеть без DNS-серверов; группа без входящего TCP 22 или без исходящего системного трафика (метаданные, DHCP).
- `deploy --json` печатает результат в stdout (`deployed` / `unchanged`).
- Предупреждения compose о `build:`, `env_file:`, локальных томах и файлах `secrets`/`configs` — до превью.
- Ожидание ВМ в `deploy`: строка с таймером и состоянием.
- Корневая справка `evo --help` по группам команд, коды выхода — в конце.
- `evo init` предупреждает, если нет compose-файла.

### Исправлено

- MCP `destroy` без записи о FIP находил по имени и FIP ВМ `<имя>-2`: при двух ВМ `web` и `web-2` FIP ВМ `web` не освобождался; теперь имя сверяется точно, из нескольких — привязанный к ВМ.
- Kafka/Redis: список кластеров читается по страницам (`page_size=100`, `next_page_token`); группы узлов mk8s — тоже.
- `evo k8s kubectl/apply/helm` печатают вывод kubectl как есть, а не таблицей.
- Деревья с `--json`: при ошибке инструмента stdout пуст.
- Английская справка `deploy`, `logs`, `destroy` (`EVO_LANG=en`) больше не пустая.
- `evo doctor` без ключа — предупреждение в строке config, а не «ок».
- Первый опрос ВМ в `deploy` и `destroy` — сразу, а не через интервал.
- Стек: шаг `vm` не создаёт ВМ повторно после ответа-ошибки и не усыновляет чужую ВМ с тем же именем.
- ВМ в `error_creating` записывается в state со статусом `error`; отказ ключа SSH и смена ключа хоста — свои статусы, а не `ssh_timeout`.
- Диагностика установки Docker: вывод последней упавшей попытки и диагноз (DNS, apt-зеркало) в подсказке.
- Сообщения `STATE_CORRUPTED` и `STATE_LOCKED` — по-русски.
- `evo version` у сборки из checkout показывает версию модуля и коммит.
- `install.sh` проверяет подпись релиза и с cosign v2.
- Пароль образа — один на все парольные поля; обязательное `fqdn` РЕД ОС заполняется именем ВМ.
- Превью ВМ: проверка сети — после цены и в своём окне 5 с, медленный список правил не оставляет превью без цены.
